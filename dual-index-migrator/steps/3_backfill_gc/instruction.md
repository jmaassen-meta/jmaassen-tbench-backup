User Store API — `dual_index/user_store.py`

| Class / Method | Signature | Behavior |
|---|---|---|
| UserStore | `UserStore(base_dir, num_shards)` | File-backed store for user blobs sharded by `uid`, stored under `base_dir` (for example a `users` tree). Each blob is a dict that must contain `username` (str, same lowercase 3-30 rules as the index — `^[a-z][a-z0-9._]{2,29}$`), `uid` (int, not bool, equal to the key it is stored under), and `universe` (str, must be `"ig"` or `"threads"`); extra keys are allowed and ignored. Universe is immutable — once a blob is created for a uid with universe `ig` or `threads`, a later `put` for that same uid with a different universe must raise `ValueError` and not modify the stored blob. All universe rules are tested via the API, not via simulated file corruption. |
| put | `put(uid, blob)` | Stores a blob for the `uid`, picking the shard deterministically via a stable hash (not Python's salted `hash()`), preserving the blob exactly. Raises `ValueError` if `uid` is not an int (not bool), `blob` is not a dict, or required keys are missing or `universe` is not `ig`/`threads`, or username fails validation, or `uid` does not match `blob["uid"]`, or universe would mutate an existing blob's universe. Is file-backed under `base_dir` so CLI and API see the same data. |
| get | `get(uid)` | Returns the blob dict for the `uid` or `None` if absent. |
| shards | `shards()` | Returns `num_shards`. |

Backfill API — `dual_index/backfill.py`

| Function | Signature | Behavior |
|---|---|---|
| backfill | `backfill(base_dir, num_shards)` | Scans all shards in both IG and Threads index trees and in the user blob store under `base_dir`. For every username it checks the current format and the corresponding blobs: single-format entries should be flagged as needing backfill to dual, dual entries should have consistent IG, Threads, and blob state. It should verify that the index's username matches the blob's username for each pointed-to uid, that the blob's universe matches the expected universe for that index entry, and that the blob's universe has not been mutated. It must not create missing blobs — it only verifies and reports. Returns a count dict with keys `total`, `already_dual`, `needs_backfill`, `consistent`, `inconsistent`, `errors` (and may include others). Must be idempotent — running it twice should report the same counts. Each username check must respect per-username serialization — if a username is currently locked (including an external hold condition), it should be skipped or reported as busy, not deadlock. All checks are via the API. |
| gc_dangling | `gc_dangling(base_dir, num_shards)` | Scans the username index (both IG and Threads trees) and the user blob store for dangling pointers — cases where the index points to a uid whose blob is missing, or where the blob's stored username or universe does not match the index's username and expected universe, or where a Threads index entry exists without a corresponding IG entry. For a mismatched `blob.username`, repair must work as follows: if the blob's username is available in the index (meaning no index entry exists for that blob username, or the index entry for that blob username already points to this same uid), then update the available index entry to point at the blob and delete the initial mismatched index entry; otherwise, if the blob's username is not available (already taken by a different uid), then update the blob's username to match the original index lookup (keeping `blob.universe` unchanged, since universe is immutable). This repair must be per-username atomic and crash-safe and must not create missing blobs beyond the repair. Returns a count dict with keys `scanned`, `dangling_found`, `repaired`, `removed` (example names, but `dangling_found`/`repaired` are checked). |
| verify | `verify(base_dir, num_shards)` | Scans all shards in the index and blob stores and checks that every index record decodes cleanly, that single-format entries have no Threads counterpart and have a matching blob with correct universe, that linked entries have both IG and Threads index entries and blobs for both uids with matching usernames and correct universes, and that unlinked entries have no Threads entry and only an ig blob. Also checks that no index points to a blob whose username or universe differs, and that no blob has had its universe mutated. Returns a dict with exact keys `total`, `consistent`, `inconsistent`, and `inconsistent_users` (sorted list; hidden tests now accept `inconsistent_users` or `inconsistent_usernames`, but `inconsistent_users` is preferred). Does not modify data and does not create blobs. |

Atomic coordination with blobs — from this step onward, the atomic operations introduced in the previous step (`link`, `unlink`, `rename`) must also atomically coordinate the user blob store. For example, `link` must create or update blobs for the new `ig_uid` and `threads_uid` with the correct universe and username, `unlink` must handle the blob for the unlinked state, and `rename` must atomically move the index entries for both usernames across both IG and Threads shards *and* update the corresponding blob(s) for the moved uid(s) so that `blob.username` matches the new index username and `blob.universe` remains correct and immutable. All of these must use the same per-username serialization as the index writes, so a crash leaves index and blobs either fully updated or untouched. All universe rules are tested via the API — hidden tests will verify that attempts to mutate universe or write with mismatched universe fail via the API.
