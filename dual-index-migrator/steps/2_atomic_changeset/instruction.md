Now that the single and dual record formats and sharded storage are in place, let's add atomic cross-universe and cross-shard operations — the pattern that made the 1.5B/day username service hard. In production the username index is split by universe: IG and Threads each have their own sharded store, so even a single logical username touches two physical shard trees.

Please extend the model under /app/dual_index. The foundation from the previous step stays as-is (dual_index/encoding.py, dual_index/shard.py, dual_index/store.py, and the init/write/read commands). Hidden tests will import the exact new paths below via PYTHONPATH=/app.

| Module | Key symbols | Purpose |
|---|---|---|
| dual_index/atomic.py | AtomicIndex | Cross-universe, cross-shard atomic operations with per-row global locking |
| dual_index/cli.py (extended) | link, unlink, rename commands | Command-line entry points for atomic operations |

Add per-universe, cross-shard atomic operations in `dual_index/atomic.py` with an `AtomicIndex(base_dir, num_shards)` that maintains two separate sharded stores (one for IG, one for Threads) under `base_dir`, a durable write-ahead log under `base_dir` (for example `wal.jsonl` with intent/commit sharing the same `id`), and per-username file-backed locks observable across processes (for example `.lock_<username>` and hold marker `.hold_<username>` under `base_dir` that tests pre-create). Implement `link`, `unlink`, `rename`, and `read` with all-or-nothing semantics: journal an intent (capture old snapshots, with a shared `id` linking intent and commit) before any shard writes, hold the per-username lock(s) for the whole operation, apply shard writes, then commit and release; on entry to any operation, if a journal entry without a matching commit exists, restore old snapshots, delete any partial shard entries, release locks, and — for `read` silently return the committed value, for others raise `ValueError` so the caller sees an error but the next operation sees a clean state. `rename` must move a username across both universes and shards only when the destination is free in both, must reject same-name renames, and must acquire the two locks in a fixed global order (`sorted` order) to avoid deadlock. For example, a straightforward implementation is: append `{"id": "<uuid>", "state": "intent", ...}` to the log, create lock file(s), do shard writes, append `{"id": "<uuid>", "state": "commit"}`, then remove lock(s); on crash, the next operation finds the intent without commit, restores `old_*`, deletes partials, removes locks, and surfaces an error (except `read` which recovers silently). Operations must treat a pre-existing hold marker file (for example `.hold_<username>` under `base_dir`) for an affected username as a held lock and fail cleanly without leaving stale locks. Extend the CLI with `link`/`unlink`/`rename` subcommands and update `init` to create the per-universe trees. Keep everything file-backed, deterministic, and offline. The log/lock file layout under `base_dir` (for example `wal.jsonl`, `.lock_<username>`, `.hold_<username>`) is the observable contract.

Atomic API — `dual_index/atomic.py`

| Class / Method | Signature | Behavior |
|---|---|---|
| AtomicIndex | `AtomicIndex(base_dir, num_shards)` | Wraps two sharded stores (IG and Threads) under `base_dir` with crash-safe atomicity and per-username serialization. Any username being operated on must be serialized across both universes until the operation is complete — either successfully committed or fully recovered — so the next operation sees a clean state. No explicit recover command is needed; recovery is automatic on next access. |
| link | `link(username, ig_uid, threads_uid)` | Atomically links a username: creates or updates the dual state by writing the username to both IG and Threads shards in one all-or-nothing operation. Must serialize on that username across both universes for the entire operation. On crash, auto-recover both universes and return an error, leaving both stores in pre-operation state. |
| unlink | `unlink(username)` | Atomically unlinks a username: removes the Threads entry and updates the IG entry to unlinked. Must serialize across both universes with same auto-recovery. Raises `ValueError` if absent or already unlinked. |
| rename | `rename(from_user, to_user)` | Atomically moves a username across both universes and shards only if destination is free in both, preserving `ig_uid`, `threads_uid`, `link_state`, `format` and updating `username` to `to_user`. Must serialize on both usernames in a fixed global order to avoid deadlock and fail if `from_user == to_user` or `from_user` absent or `to_user` taken. On crash, auto-recover both. |
| read | `read(username)` | Returns the decoded record or `None`, reflecting only committed state across both universes. Must respect ongoing serialization and silently auto-recover any pending journal entry before returning committed value without raising, so the next mutating operation sees a clean state. |

CLI — new commands on `python -m dual_index.cli` (all must be added to the same `cli.py` and work via `python -m dual_index.cli <command> --help`)

| Command | Options | Behavior |
|---|---|---|
| link | `--user NAME --ig-uid A --threads-uid B --base-dir PATH` (default `./data`) | Atomically links via `AtomicIndex` link. Serializes on that user across both stores; on crash auto-recovers and exits non-zero. |
| unlink | `--user NAME --base-dir PATH` | Atomically unlinks across both universes, same serialization and recovery, non-zero on failure. |
| rename | `--from USER --to USER --base-dir PATH` | Atomically renames across both universes and shards only if destination free. Serializes on both usernames in deterministic order; on crash auto-recovers and exits non-zero. |

Existing `init`, `write`, and `read` commands keep working as before, but `init` should now create the per-universe sharded trees and record shards and format. The new operations should be usable like `python -m dual_index.cli link --user alice --ig-uid 100 --threads-uid 200 --base-dir ./data` then `python -m dual_index.cli read --user alice --base-dir ./data --output json` showing a linked dual record, and `python -m dual_index.cli rename --from bob --to alice --base-dir ./data` only succeeding when alice is free in both universes.

Keep everything deterministic and offline.
